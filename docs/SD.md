# STM32F769I-DISC1 SD/MMC Handling and Debugging Guide

This guide covers the hardware pins, HAL API, direct register access, initialization flow, and practical debugging of the SD card slot on the STM32F769I-DISC1 board used in saramOS.

## 1. SDMMC1 Pin Mapping

The STM32F769I-DISC1 SD card slot is connected to the **SDMMC1** peripheral. All data/clock/command pins use **AF12**.

| Pin  | Signal | Direction | AF  | Pull/Setting                     |
|------|--------|-----------|-----|----------------------------------|
| PC8  | D0     | IO        | 12  | pull-up (`GPIO_PUPD_UP`)         |
| PC9  | D1     | IO        | 12  | pull-up                          |
| PC10 | D2     | IO        | 12  | pull-up                          |
| PC11 | D3     | IO        | 12  | pull-up                          |
| PC12 | CK     | OUT       | 12  | no pull (`GPIO_PUPD_NONE`)       |
| PD2  | CMD    | IO        | 12  | pull-up                          |
| PG2  | CD     | IN        | -   | input, pull-up (active low)      |

- **D0~D3**: 4-bit data bus. The SD spec requires pull-ups on the data lines.
- **CK**: SD card clock. No pull-up.
- **CMD**: Command/response line. Pull-up is required.
- **CD (Card Detect)**: Card insertion detect. **Active low**: PG2 reads as `0` when a card is inserted.

## 2. Pin Role Details

### D0~D3 (PC8~PC11)
- 4-bit data bus to the SD card.
- Pull-ups are mandatory to keep the lines high during idle states.
- In 1-bit mode, only D0 is used; D1~D3 still stay pulled up.

### CK (PC12)
- Clock generated by SDMMC1.
- Identification phase: 100~400 kHz. Data transfer phase: MHz range.

### CMD (PD2)
- Bidirectional command/response line.
- Pull-up is required because some SD command phases use open-drain behavior.

### CD (PG2)
- Connected to the mechanical card-detect switch in the slot.
- If wiring or pin configuration is wrong, the firmware reports "no card detected" even when a card is present.

## 3. Controlling Pins via HAL

API declarations are in `include/hal/stm32f769i-disc1.h` and `include/hal/hal_gpio.h`.

### GPIO Initialization

```c
#include <hal/stm32f769i-disc1.h>
#include <hal/hal_gpio.h>

/* Data lines: AF12, high speed, pull-up */
hal_gpio_init_af(GPIOC_BASE, 8, 12, GPIO_SPEED_HIGH, GPIO_PUPD_UP);
hal_gpio_init_af(GPIOC_BASE, 9, 12, GPIO_SPEED_HIGH, GPIO_PUPD_UP);
hal_gpio_init_af(GPIOC_BASE, 10, 12, GPIO_SPEED_HIGH, GPIO_PUPD_UP);
hal_gpio_init_af(GPIOC_BASE, 11, 12, GPIO_SPEED_HIGH, GPIO_PUPD_UP);

/* Clock: AF12, high speed, no pull */
hal_gpio_init_af(GPIOC_BASE, 12, 12, GPIO_SPEED_HIGH, GPIO_PUPD_NONE);

/* CMD: AF12, high speed, pull-up */
hal_gpio_init_af(GPIOD_BASE, 2, 12, GPIO_SPEED_HIGH, GPIO_PUPD_UP);

/* CD: input with pull-up (active low) */
hal_gpio_init_input(GPIOG_BASE, 2, GPIO_PUPD_UP);
```

### Reading/Writing GPIO

```c
/* Read PG2/CD: 0 means card inserted */
int cd = hal_gpio_read(GPIOG_BASE, 2);
if (cd == 0) {
    /* card present */
}

/* Drive an output pin high/low (e.g. LED) */
hal_gpio_write(GPIOG_BASE, 2, 1); /* high */
hal_gpio_write(GPIOG_BASE, 2, 0); /* low */
```

Convenience wrappers for input-only pull configuration:

```c
void hal_gpio_init_pullup(uint32_t port_base, uint8_t pin);
void hal_gpio_init_pulldown(uint32_t port_base, uint8_t pin);
```

## 4. Direct Register Access

Use the macros and structs defined in `include/hal/stm32f769i-disc1.h`.

### GPIO Registers

```c
/* Set PG2 MODER to input (MODER2 = 00) */
volatile uint32_t *pg_moder = gpio_reg(GPIOG_BASE, GPIO_MODER);
*pg_moder &= ~(3U << (2 * 2));   /* PG2: input mode */

/* PG2 PUPDR: pull-up (01) */
volatile uint32_t *pg_pupdr = gpio_reg(GPIOG_BASE, GPIO_PUPDR);
*pg_pupdr = (*pg_pupdr & ~(3U << (2 * 2))) | (1U << (2 * 2));

/* Read PG2 input */
volatile uint32_t *pg_idr = gpio_reg(GPIOG_BASE, GPIO_IDR);
int cd_low = (*pg_idr >> 2) & 1U;   /* 0 means card present */

/* Drive PC8 high/low directly */
volatile uint32_t *pc_bsrr = gpio_reg(GPIOC_BASE, GPIO_BSRR);
*pc_bsrr = (1U << 8);      /* PC8 high */
*pc_bsrr = (1U << (8+16)); /* PC8 low */
```

### SDMMC1 Registers

`SDMMC1` is a pointer to `sdmmc1_regs_t`.

```c
uint32_t pwr   = SDMMC1->POWER;
uint32_t clkcr = SDMMC1->CLKCR;
uint32_t sta   = SDMMC1->STA;
uint32_t icr   = SDMMC1->ICR;

/* Clear static flags */
SDMMC1->ICR = SDMMC_ICR_STATIC_MASK;
```

Key `STA` flags:

| Bit | Macro               | Meaning                                      |
|-----|---------------------|----------------------------------------------|
| 6   | SDMMC_STA_CMDREND   | Command response received                    |
| 7   | SDMMC_STA_CMDSENT   | Command sent (no-response commands)          |
| 8   | SDMMC_STA_DATAEND   | Data transfer finished                       |
| 10  | SDMMC_STA_DBCKEND   | Data block sent/received                     |
| 2   | SDMMC_STA_CTIMEOUT  | Command timeout                              |
| 3   | SDMMC_STA_DTIMEOUT  | Data timeout                                 |
| 0   | SDMMC_STA_CCRCFAIL  | Command CRC failure                          |
| 1   | SDMMC_STA_DCRCFAIL  | Data CRC failure                             |

### SDMMC1 Clock Source

SDMMC1 does **not** use the AHB bus clock directly. It has a dedicated functional clock selected by `RCC_DCKCFGR2` bit 28 (`SDMMC1SEL`):

```c
#define RCC_DCKCFGR2    (*(volatile uint32_t *)(RCC_BASE + 0x94U))
#define RCC_DCKCFGR2_SDMMC1SEL  (1U << 28)
```

- `SDMMC1SEL = 0` (reset default): uses `PLL48CLK`. If the PLL is not configured, this clock is dead and SDMMC1 cannot send any command.
- `SDMMC1SEL = 1`: uses `SYSCLK`. With the default HSI 16 MHz system clock, SDMMC1 runs at 16 MHz and the 400 kHz identification clock is generated by the internal divider.

In saramOS, the minimal system init keeps HSI and does **not** enable a PLL. Therefore the driver must set:

```c
RCC_DCKCFGR2 |= RCC_DCKCFGR2_SDMMC1SEL;
```

Without this, `CMD0` times out with `SDMMC1->STA == 0x00000000` because the command state machine has no clock.

## 5. Sending SDMMC Commands Manually

### CMD0 (GO_IDLE_STATE), no response

CMD0 has no response, so the firmware waits for `CMDSENT`, not `CMDREND`.

```c
/* Enable clock and power */
RCC_AHB2ENR |= RCC_AHB2ENR_SDMMC1EN;
RCC_DCKCFGR2 |= RCC_DCKCFGR2_SDMMC1SEL;
SDMMC1->POWER = (SDMMC_POWER_PWRCTRL_ON << SDMMC_POWER_PWRCTRL_Pos);
SDMMC1->CLKCR = SDMMC_CLKCR_CLKEN | (20U << 0); /* ~400 kHz from 16 MHz */

/* Clear static flags */
SDMMC1->ICR = SDMMC_ICR_STATIC_MASK;

/* CMD0: no response, arg = 0 */
SDMMC1->ARG = 0;
SDMMC1->CMD = (0U << SDMMC_CMD_CMDINDEX_Pos)
            | SDMMC_CMD_CPSMEN;

/* Wait for CMDSENT or CTIMEOUT */
while (!(SDMMC1->STA & (SDMMC_STA_CMDSENT | SDMMC_STA_CTIMEOUT)))
    ;

if (SDMMC1->STA & SDMMC_STA_CTIMEOUT) {
    SDMMC1->ICR = SDMMC_ICR_CTIMEOUTC;
    /* timeout */
} else {
    SDMMC1->ICR = SDMMC_ICR_CMDSENTC;
    /* CMD0 sent */
}
```

### CMD8 (SEND_IF_COND), R7 response

```c
SDMMC1->ARG = 0x1AA;
SDMMC1->CMD = (8U << SDMMC_CMD_CMDINDEX_Pos)
            | SDMMC_CMD_WAITRESP_SHORT
            | SDMMC_CMD_CPSMEN;

while (!(SDMMC1->STA & (SDMMC_STA_CMDREND | SDMMC_STA_CTIMEOUT)))
    ;

if (SDMMC1->STA & SDMMC_STA_CMDREND) {
    uint32_t resp = SDMMC1->RESP1;
    SDMMC1->ICR = SDMMC_ICR_CMDRENDC;
}
```

## 6. SD Initialization Flow

Typical SD card initialization sequence:

1. Configure pins (AF12, pull-ups, CD input).
2. Enable SDMMC1 peripheral clock and select functional clock source.
3. Power on and set identification clock (<= 400 kHz).
4. `CMD0` → idle state.
5. `CMD8` → voltage check (SDHC/SDXC respond).
6. `ACMD41` (HCS=1) → read OCR and CCS bit.
7. `CMD2` → read CID.
8. `CMD3` → get RCA.
9. `CMD9` → read CSD and compute capacity.
10. `CMD7` → select card.
11. `ACMD6` → set 4-bit bus.
12. `CMD16` → set block length to 512 bytes.
13. Raise clock to default speed (~8 MHz).

## 7. Reverse-Engineering Findings

### Symptom: `CMD0 rc=-2, sta=0x00000000`

- `rc=-2` means the command timed out.
- `sta=0x00000000` means the SDMMC command state machine did nothing: neither `CMDSENT` nor `CTIMEOUT` fired.
- Root cause: SDMMC1 functional clock is missing. Set `RCC_DCKCFGR2_SDMMC1SEL` to use `SYSCLK` when PLL is not enabled.

### Symptom: `PG2/CD` reads high with a card inserted

- PG2 is active low. If it reads `1`, the card-detect switch is open.
- Causes:
  - Card not fully inserted.
  - Mechanical switch failure.
  - Wrong pull configuration (pull-down instead of pull-up would invert the logic).
  - PG2 pin not connected to the switch.

### Symptom: `PG2/CD` is low before `sd init`, but high after `sd init`

- `configure_sd_pins()` reconfigures PG2 as input pull-up. If the line goes high after that, the card either disconnected during initialization or the switch bounces.
- Check the card slot physically and compare `pin read PG2` before and after `sd init`.

### Symptom: `sd init` returns `FR_NOT_READY` (3)

- `disk_initialize()` failed, i.e. `hal_sdmmc_init()` returned an error.
- Read the step-by-step debug output to see which command fails.

### Symptom: `sd init` returns `FR_NO_FILESYSTEM` (13)

- SDMMC initialization succeeded, but FatFs could not find a FAT volume.
- Verify the card is formatted as FAT32.
- If the card uses GPT, enable `FF_LBA64=1` and `FF_FS_EXFAT=1` in `ffconf.h`.
- The default MS Basic Data partition GUID (`EBD0A0A2-B9E5-4433-87C0-68B6B72699C7`) is recognized by FatFs.

## 8. Debug CLI

The saramOS example includes `pin` and `inp` commands for GPIO debugging.

### `pin` command

```text
pin pullup   <PA0>            # input with pull-up
pin pulldown <PA0>            # input with pull-down
pin inp      <PA0>            # input (no pull)
pin out      <PA0>            # output (high speed)
pin write    <PA0> 0|1        # drive high/low
pin read     <PA0> <n> ascii  # sample n times, print '0'/'1'
pin read     <PA0> <n> raw    # sample n times, pack into hex bytes
```

Supported pins: `PA0` ~ `PK15` (ports A~K, pins 0~15). Both `PA0` and `A0` forms are accepted.

### `inp` command

Sample the last pin configured by `pin pullup`, `pin pulldown`, or `pin inp`.

```text
inp read <n> ascii
inp read <n> raw
```

### Examples

```text
saramOS> pin pullup PG2
saramOS> pin read PG2 10 ascii
0000000000
saramOS> pin read PG2 16 raw
00
```

## 9. Step-by-Step Debug Checklist

Run in this order and compare results:

```text
saramOS> pin pullup PG2
saramOS> pin read PG2 10 ascii
saramOS> sd inspect
saramOS> sd init
saramOS> sd inspect
```

Expected:
- `pin read PG2` returns `0000000000` (card inserted).
- After `sd inspect` before `sd init`, `POWER`/`CLKCR`/`STA` are `0` because initialization has not run.
- After `sd init`, step-by-step debug output shows each command succeeding.
- After successful init, `sd inspect` shows non-zero `POWER`/`CLKCR` and `capacity blocks`.

If `CMD0` fails with `sta=0x00000000`, check `RCC_DCKCFGR2_SDMMC1SEL`.
